Introduction

This post gives a map of the whole website before we go into the details in the next posts. The website is static: there is no server-side code and no database. It is a set of HTML, CSS and JavaScript files stored in a GitHub repository and served for free by GitHub Pages. Everything that looks dynamic (the shared navigation bar, the list of blog posts, the search, the filters of the theses) is done by the browser with a few lines of JavaScript.

This choice keeps the website fast, free to host, easy to back up (it is just a Git repository) and easy to change: a new post is a new HTML file.

The pages

Each section of the website is one HTML file in the root of the repository. Thanks to GitHub Pages the extension can be omitted, so curriculum.html is also reachable as /curriculum.

  • index.html: the home page;
  • curriculum.html: the CV, with the list of publications;
  • blog.html and blogPost.html: the list of blog posts and the page that shows a single post;
  • tags.html and tagArticles.html: blog tags and the posts with a given tag;
  • projects.html, projectArchive.html and projectPost.html: the list of projects, the list of posts of a project (like this series) and a single post;
  • theses.html: the available M.Sc. theses, with filters;
  • contact.html: contacts, map and directions.

One layout, three columns

All pages share the same layout: a navigation bar on top, three columns (the profile on the left, the content in the centre, extra links on the right) and a footer. On a phone the columns stack one below the other. The layout comes from Bulma, a CSS framework, adapted from the Icarus theme; on top of it a single stylesheet, modern.css, defines fonts, colours, spacing and the dark mode.

The parts that are identical on every page are not copied into every file. Each page contains only empty containers, and the content is loaded from the common/ folder: 

common/
├── navBar.html      navigation bar
├── leftPane.html    profile, CV and contact buttons
├── rightPane.html   right column
└── footer.html      footer

Changing the navigation bar therefore means editing one file, and the change appears on every page. The browser keeps these parts in memory while you move from one page to the next, so they are shown immediately.

Where the content lives

The same idea is used for the content: the pages are templates, and the text is in separate files loaded when needed. 

posts/
├── blog/
│   ├── index.json          list of the blog posts
│   ├── collectify.html
│   └── tex2html.html
└── projects/
    ├── website.html        list of posts of this project
    └── websitePosts/
        └── overview.html   this post
homePane.html               text of the home page
pubs.html                   list of publications
thesis-card.html            the theses

For example, the address projectPost?project=website&post=overview tells projectPost.html to load posts/projects/websitePosts/overview.html into the central column. Adding a blog post means writing its HTML file and adding its name to index.json; the list of posts, the tags and the search update by themselves.

Styles, scripts and images 

assets/
├── css/
│   ├── default.css    the base theme (Bulma + Icarus)
│   └── modern.css     the restyle: fonts, colours, dark mode
├── js/
│   ├── partials.js    loads the shared parts (and keeps them in memory)
│   ├── script.js      dark mode switch
│   ├── search.js      search
│   ├── tableContent.js table of contents of the posts
│   └── ...
└── images/

There is no build step: what is in the repository is exactly what the browser receives. The only external libraries are loaded from public CDNs (jQuery, Font Awesome for the icons, Fuse.js for the search).

How it is updated

The website is developed on a separate branch and tested on the local computer with a small Python server (tools/serve.py) that behaves like GitHub Pages. When everything works, the branch is merged into main and pushed: GitHub Pages publishes the new version within a minute or two.
