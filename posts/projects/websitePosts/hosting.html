Introduction

GitHub Pages is a free service of GitHub that publishes the files of a repository as a website. There is nothing to install on a server and nothing to pay: you push your files, and a minute later they are online. This post explains how this website is published and how it is tested locally before publishing.

The repository

A personal website lives in a repository with a special name: <username>.github.io, where <username> is your GitHub account. This website, for example, is in the repository fghio.github.io and is published at https://fghio.github.io.

  1. Create a new public repository named <username>.github.io.
  2. Add a file index.html at its root: this is the home page.
  3. In Settings → Pages, choose Deploy from a branch, branch main, folder / (root).
  4. Push. After a minute or two the website is online at https://<username>.github.io.

Every following push to main publishes a new version: the history of the website is the history of the repository, and any change can be undone with Git.

Addresses without .html

GitHub Pages serves a file also when the address omits the .html extension: /curriculum shows curriculum.html. This makes addresses easier to read and to share (“go to fghio.github.io/curriculum”). All the internal links of this website are written without the extension, and old links with .html still work. A tiny script in the <head> of each page also removes the extension from the address bar when someone arrives from an old link: 

<script>
  (function () {
    var p = location.pathname;
    if (/\.html$/.test(p))
      history.replaceState(null, "",
        p.replace(/(^|\/)index\.html$/, "$1").replace(/\.html$/, "")
        + location.search + location.hash);
  })();
</script>

A folder with an index.html inside behaves the same way: howTo/index.html is reachable as /howTo/.

Testing on your computer

Opening the HTML files directly from the disk does not work well: the browser blocks the requests that load the shared parts and the posts. You need a small local web server. Python has one built in (python3 -m http.server), but it does not understand addresses without .html. This website uses a slightly extended version, tools/serve.py, which behaves like GitHub Pages:

  • /curriculum serves curriculum.html;
  • folders without index.html return 404 instead of listing their files;
  • nothing is cached, so every change is visible at the next reload.
python3 tools/serve.py        # http://localhost:8000
python3 tools/serve.py 8080   # another port

A safe workflow

Changes are never made directly on main, which is what the visitors see. The work happens on a separate branch (here called development), is checked locally with the server above, and only then is merged into main and pushed. If something goes wrong, main is untouched and the previous version is one command away. 

git switch development
# ... edit, test on http://localhost:8000 ...
git commit -am "New post"
git switch main
git merge development
git push
