Introduction

The navigation bar, the two side columns and the footer are the same on every page. Copying them into eleven files would mean editing eleven files for every change. Instead, they are written once, in the common/ folder, and inserted into each page by a small script, partials.js.

Empty containers

Each page contains only empty placeholders where the shared parts go, followed by a short script that fills them: 

<div id="navBarContainer"></div>
<!-- ... page content ... -->
<div id="footerContainer"></div>

<script id="mx-partials">
  loadPartial("#navBarContainer", "./common/navBar.html");
  loadPartial("#leftPaneContainer", "./common/leftPane.html");
  loadPartial("#rightPaneContainer", "./common/rightPane.html");
  loadPartial("#footerContainer", "./common/footer.html");
</script>

The calls are placed right after the containers, not at the end of the page, so that the parts are inserted as early as possible.

Keeping the parts in memory

Downloading the four parts at every page change would make them appear a moment after the rest of the page. loadPartial avoids this with the browser's session storage, a small memory that lasts as long as the tab is open:

  1. If the part is already in memory, it is inserted immediately.
  2. In any case, the current version is downloaded in the background; if it has changed, it is saved and used from the next page on.
  3. When a page has finished loading, the parts not yet in memory are downloaded in advance.
window.loadPartial = function (selector, url) {
  var el = document.querySelector(selector);
  var cached = sessionStorage.getItem("partial:" + url);
  if (cached !== null) render(el, cached);          // immediately, from memory

  fetch(url, { cache: "no-cache" }).then(r => r.text()).then(function (html) {
    if (html === cached) return;
    sessionStorage.setItem("partial:" + url, html); // fresh copy for the next page
    if (cached === null) render(el, html);          // first visit: show it now
  });
};

The result is that moving from one page to another, only the central column changes: the navigation bar and the side columns stay where they are.

Parts with scripts

Some parts contain scripts (the dark mode switch, the search button). When HTML is inserted from JavaScript, the browser does not run the scripts it contains, so render recreates each <script> element after inserting the rest. This keeps the shared parts self-contained: a part brings its own behaviour with it.

Waiting for the parts

Chrome supports a hint that delays the first drawing of the page until a given element has been parsed. Pointing it to the script that loads the parts means the page is drawn once, already complete, instead of drawing the content first and the parts a moment later: 

<link rel="expect" href="#mx-partials" blocking="render">

Browsers that do not know this hint simply ignore it.
