Introduction

The navigation bar, the two side columns and the footer are the same on every page. Copying them into eleven files would mean editing eleven files for every change, and sooner or later the copies would differ. In this post we write them once, in a common/ folder, and insert them into every page with a small script.

Then we make them fast: when moving from one page to another, the shared parts should not disappear and reappear, but stay where they are while only the central content changes.

Write once, insert everywhere

The parts

Each shared part is a fragment of HTML, without <html> or <head>: just the markup of that part. 

common/
├── navBar.html      navigation bar
├── leftPane.html    profile, CV and contact buttons
├── rightPane.html   right column
└── footer.html      footer
<!-- common/navBar.html (simplified) -->
<nav class="navbar navbar-main">
  <div class="container navbar-container">
    <a class="navbar-item navbar-logo" href="./">FGh.io</a>
    <div class="navbar-start">
      <a class="navbar-item" href="./curriculum">Curriculum</a>
      <a class="navbar-item" href="./blog">Blog</a>
      <a class="navbar-item" href="./projects">Projects</a>
      <a class="navbar-item" href="./theses">Theses</a>
      <a class="navbar-item" href="./contact">Contact</a>
    </div>
  </div>
</nav>

The containers

Each page contains only empty placeholders where the parts go, followed by a short script that fills them: 

<div id="navBarContainer"></div>
<!-- ... the page: columns, content ... -->
<div id="footerContainer"></div>

<script id="mx-partials">
  loadPartial("#navBarContainer", "./common/navBar.html");
  loadPartial("#leftPaneContainer", "./common/leftPane.html");
  loadPartial("#rightPaneContainer", "./common/rightPane.html");
  loadPartial("#footerContainer", "./common/footer.html");
</script>

The calls are placed right after the containers, not at the end of the page or inside a “page loaded” handler, so that the parts are inserted as early as possible. A page that does not need the right column (the post pages, for example) simply omits that container and that call.

The simplest version

With jQuery, the simplest implementation is one line per part: 

$("#navBarContainer").load("./common/navBar.html");

It works, but every page change downloads the four parts again, and they appear a moment after the rest of the page. The next section fixes this.

Keeping the parts in memory

The browser offers a small key–value memory, the session storage, that lasts as long as the tab is open and survives page changes. We use it to keep a copy of each part:

  1. If the part is already in memory, insert it immediately, without waiting for the network.
  2. In any case, download the current version in the background. If it differs from the copy, save it: it will be used from the next page on.
  3. If there was no copy (the first page of the visit), insert the downloaded version as soon as it arrives.

This is the complete assets/js/partials.js, to be included in the <head> after jQuery: 

(function ($) {
  var PREFIX = "partial:v3:";

  function read(url)        { try { return sessionStorage.getItem(PREFIX + url); } catch (e) { return null; } }
  function write(url, html) { try { sessionStorage.setItem(PREFIX + url, html); } catch (e) {} }
  function fetchPartial(url) { return $.ajax({ url: url, dataType: "html", cache: false }); }

  // Insert the HTML, then re-create the <script> elements so that they run
  function render(el, html) {
    var nodes = $.parseHTML(html, document, true) || [];
    var scripts = [];
    el.textContent = "";
    nodes.forEach(function (node) {
      if (node.nodeName === "SCRIPT") scripts.push(node);
      else el.appendChild(node);
    });
    scripts.forEach(function (old) {
      var s = document.createElement("script");
      if (old.src) { s.src = old.getAttribute("src"); s.async = false; }
      else s.text = old.text;
      el.appendChild(s);
    });
  }

  window.loadPartial = function (selector, url) {
    var el = document.querySelector(selector);
    if (!el) return;
    var cached = read(url);
    if (cached !== null) render(el, cached);       // 1. immediately, from memory

    fetchPartial(url).done(function (html) {       // 2. always check for a newer version
      if (html === cached) return;
      write(url, html);
      if (cached === null) render(el, html);       // first visit: show it now
    });
  };
})(jQuery);

Why not show the new version immediately

When a part has changed (because you just published a new menu), the script saves the new version but does not replace the one already on screen. Replacing it would make the part flicker and run its scripts twice; showing the new version from the next page is invisible to the visitor.

The version prefix

The keys start with partial:v3:. If the way parts are stored ever changes, increasing the number makes every browser ignore the old copies instead of reusing them.

Errors

Every access to the session storage is wrapped in try: in some private windows it is not available, or it is full. In that case the script simply behaves like the simplest version, downloading the parts every time.

Parts with scripts

Some parts contain scripts: the left column wires up the “Hire me” button, the navigation bar the search and the dark mode switch. When HTML is inserted from JavaScript, the browser does not run the <script> elements it contains. That is why render inserts everything else first, then creates a new script element for each old one: newly created scripts do run.

Setting async = false on external scripts keeps them in their original order, which matters when one script depends on another.

Drawing the page once

Even with the parts in memory, the browser could draw the page once without them and once again a few milliseconds later. Chrome supports a hint that delays the first drawing until a given element has been parsed. Pointing it to the script that loads the parts means the first frame already contains them: 

<head>
  ...
  <link rel="expect" href="#mx-partials" blocking="render">
</head>

Browsers that do not know this hint ignore it, and nothing breaks. Combined with the cache and with the page transitions described in polish and performance, moving between pages feels like changing only the central column.

Try it yourself

  1. Move your navigation bar into common/navBar.html and load it with the one-line jQuery version.
  2. Replace it with partials.js.
  3. Open the developer tools (F12), tab Application → Session storage, and watch the parts being saved as you navigate.
  4. Change the menu, reload twice, and see when the change appears.
