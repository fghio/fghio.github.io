Introduction

The blog has a list of posts shown as cards with pagination, a page for each post, a page of tags, and comments. There is no database and no build step: a post is an HTML file that carries its own metadata, and a short JSON file lists the posts. In this post we build all of it.

A post

Each post is a file in posts/blog/. Like the shared parts, it is a fragment of HTML: it will be inserted into the central column of blogPost.html. Besides the text, it carries its metadata in a data-metadata attribute, as JSON: 

<div class="card">
  <article class="card-content article" data-metadata='{
    "creationDate": "2024-11-23",
    "lastModificationDate": "2024-11-24",
    "title": "collectify: gotta collect &apos;em all",
    "readTime": "5 min",
    "tags": ["python", "app", "utility"],
    "description": "The tool for collectors. Provided they know how to run a python script."
  }'>

    <h1 class="title">collectify: gotta collect 'em all</h1>
    <div class="content">
      <p>The text of the post...</p>
    </div>

  </article>
</div>

Keeping the metadata inside the post means there is a single file to write and nothing to keep in sync: the list of posts, the tags and the search all read the same attribute. Note the single quotes around the attribute, so that the JSON can use double quotes, and &apos; for an apostrophe inside it.

The list of posts

index.json

A static website cannot ask the server for the list of files in a folder, so the posts are listed by hand in posts/blog/index.json: 

[
  { "name": "collectify.html" },
  { "name": "tex2html.html" }
]

Publishing a post therefore takes two steps: add its HTML file, and add its name here. The order in the file does not matter.

Cards and pagination

blogCard.js, included in blog.html, does the rest:

  1. downloads index.json;
  2. downloads each post and reads its data-metadata;
  3. sorts the posts by last modification date, most recent first;
  4. builds a card for each post (title, date, reading time, description, tags) and shows them four per page, with page links at the bottom.
$.getJSON("posts/blog/index.json", function (files) {
  var posts = files.map(function (f) { return f.name.replace(/\.html$/, ""); });
  // ... load each post, read data-metadata, sort by lastModificationDate ...
  showPage(1);
});

function readMetadata(html) {
  var doc = new DOMParser().parseFromString(html, "text/html");
  return JSON.parse(doc.querySelector("[data-metadata]").getAttribute("data-metadata"));
}

Each card links to blogPost?post=<name>.

The page of a post

All posts are displayed by the same page, blogPost.html: the usual layout with an empty central column. A short script reads the name of the post from the address and loads the corresponding file: 

// blogPost?post=collectify  ->  posts/blog/collectify.html
$(function () {
  var post = new URLSearchParams(location.search).get("post");
  if (!post) return;
  $.ajax({ url: "./posts/blog/" + post + ".html" })
    .done(function (html) { $(".column-main").html(html); });
});

jQuery's .html() runs the scripts contained in the post, so a post can include its own interactive parts: a calculator, a chart, the table of contents.

Comments

The comments are provided by Disqus, an external service, since a static website cannot store them. Each post ends with the Disqus snippet, which identifies the post with its address and a unique identifier: 

<div id="disqus_thread"></div>
<script>
  var disqus_config = function () {
    this.page.url = "https://fghio.github.io/blogPost?post=collectify";
    this.page.identifier = "/posts/blog/collectify.html";
  };
  (function () {
    var s = document.createElement("script");
    s.src = "//<your-shortname>.disqus.com/embed.js";
    s.setAttribute("data-timestamp", +new Date());
    document.body.appendChild(s);
  })();
</script>

The identifier must never change once the post is published, otherwise the existing comments are lost; the address can change, as long as the identifier stays the same.

Tags

tags.html shows every tag used by the posts, with the number of posts for each; tagArticles?tag=python lists the posts with a given tag. Collecting the tags means downloading every post and reading its metadata, so the result is kept in the session storage, as for the shared parts, and reused while the tab is open: 

var CACHE_KEY = "blogTags:v1";
var cached = null;
try { cached = JSON.parse(sessionStorage.getItem(CACHE_KEY)); } catch (e) {}

if (Array.isArray(cached)) {
  showTags(cached);                         // instant
} else {
  collectTags().then(function (tags) {      // download and count
    if (tags.length) sessionStorage.setItem(CACHE_KEY, JSON.stringify(tags));
    showTags(tags);
  });
}

An empty result (for example when the network is down) is not saved, so that the next page tries again.

Try it yourself

  1. Write a post with its data-metadata and add it to index.json.
  2. Open blogPost?post=<name> on the local server.
  3. Add a second post with a more recent date and check that it comes first in the list.
  4. Add a new tag and check that it appears on the tags page in a new tab.
