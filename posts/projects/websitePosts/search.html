Introduction

The magnifying glass in the navigation bar (or the keys / and Ctrl+K) opens a search over the whole website: blog posts, project posts, theses, the CV, publications and contacts. Search engines for websites usually need a server; here the browser does everything, with one script, search.js, and a small library. In this post we build the index, the matching and the search window.

Building the index

Documents

The search works on an index: a list of documents, one per result that can be shown, each with a few fields: 

{
  type: "Project",                                   // shown as a label
  section: "How to make this website",               // where it belongs
  title: "How to make this website: site search",
  tags: "",
  text: "The magnifying glass in the navigation bar ...",
  url: "projectPost?project=website&post=search"     // what to open
}

Sources

The index is built the first time the search is opened. search.js has one small function per source; each downloads the pages it needs, extracts the text and returns its documents:

SourceWhere the documents come from
HomehomePane.html, one document per section
Curriculumcurriculum.html, one per CV entry
Publicationspubs.html
Thesesthesis-card.html, one per thesis
Contactcontact.html
Blogposts/blog/index.json, then each post and its metadata
Projectseach project's timeline, then every post it links to
function indexBlog() {
  return getJSON("posts/blog/index.json").then(function (files) {
    return Promise.all(files.map(function (f) {
      var slug = f.name.replace(/\.html$/, "");
      return getText("posts/blog/" + f.name).then(function (html) {
        var doc = parse(html);
        var meta = JSON.parse(doc.querySelector("[data-metadata]").getAttribute("data-metadata"));
        return { type: "Blog", title: meta.title, tags: meta.tags.join(" "),
                 text: text(doc.querySelector(".content")),
                 url: "blogPost?post=" + slug };
      });
    }));
  });
}

Since the blog list, the theses file and the project timelines are read every time, new content enters the search by itself. Only a brand-new project has to be added to the list of projects in search.js.

Robustness and cache

All sources run in parallel, and a failing source returns an empty list instead of breaking the others. The finished index is saved in the session storage, so it is built once per tab and the following searches are instantaneous: 

var sources = [indexHome, indexCurriculum, indexPublications, indexTheses,
               indexContact, indexBlog, indexProjects];

Promise.all(sources.map(function (f) {
  return f().catch(function () { return []; });   // one broken source does not block the rest
})).then(function (lists) {
  var docs = [].concat.apply([], lists);
  sessionStorage.setItem("searchIndex:v5", JSON.stringify(docs));
});

Fuzzy matching

The matching is done by Fuse.js, a small library for fuzzy search: it tolerates typos and partial words, and ranks the results by relevance. Each field has a weight, so that a match in the title counts more than a match in the text: 

var fuse = new Fuse(docs, {
  keys: [
    { name: "title",   weight: 3 },
    { name: "tags",    weight: 1.5 },
    { name: "section", weight: 1 },
    { name: "type",    weight: 1 },
    { name: "text",    weight: 1 }
  ],
  includeMatches: true,   // positions of the matches, to highlight them
  ignoreLocation: true,   // a match at the end of a long text counts as much as at the start
  threshold: 0.3,         // tolerance: 0 = exact, 1 = matches anything
  minMatchCharLength: 2
});

var results = fuse.search("dark mode").slice(0, 12);

threshold is the main setting to tune: lower values give fewer, more precise results; higher values forgive more typos but bring in noise. 0.3 worked well for this website.

Loading the library only when needed

Fuse.js is loaded from a CDN only when the search is opened for the first time, so it costs nothing to visitors who never use it: 

function loadFuse() {
  if (window.Fuse) return Promise.resolve(window.Fuse);
  return new Promise(function (resolve, reject) {
    var s = document.createElement("script");
    s.src = "https://cdnjs.cloudflare.com/ajax/libs/fuse.js/7.0.0/fuse.min.js";
    s.onload = function () { resolve(window.Fuse); };
    s.onerror = reject;
    document.head.appendChild(s);
  });
}

The search window

The search window is created by the script the first time it is needed: a panel with an input field and a list of results, over a dimmed page. Each result shows its type, title and section, with the matching words highlighted, and links to its page.

Smarter links

Some results carry a hint for the page they open. A thesis opens theses?q=<title>, which shows that thesis only; a CV entry opens the curriculum at the right section, using an anchor (curriculum#PhDCourse).

Keyboard

The search is fully usable without the mouse: 

document.addEventListener("keydown", function (e) {
  var typing = /INPUT|TEXTAREA/.test(document.activeElement.tagName);
  if ((e.key === "k" && (e.ctrlKey || e.metaKey)) || (e.key === "/" && !typing)) {
    e.preventDefault();
    open();
  }
  if (e.key === "Escape" && isOpen()) close();
});
// in the input field: ArrowDown / ArrowUp move the selection, Enter opens it

The / shortcut is ignored while typing in a text field, otherwise it would be impossible to type a slash.

Try it yourself

  1. Build an index with two sources (the blog and one page of your choice).
  2. Search it with Fuse.js from the browser console, trying different values of threshold.
  3. Add the window and the shortcuts.
