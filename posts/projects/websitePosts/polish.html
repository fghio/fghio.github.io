Introduction

The previous posts built the features. This last one collects the details that add no feature but make the website feel quicker and more finished: transitions between pages, caching, images, phones, and a quick way to check everything before publishing.

Transitions between pages

Recent browsers can animate the change from one page to the next of the same website, with view transitions. One CSS rule enables them for every link: 

@view-transition { navigation: auto; }

By default the whole page cross-fades. For this website the shared parts should not move at all: they are the same on both pages. Giving them a view-transition-name tells the browser that they are the same element on both pages; disabling their animation makes the swap instant, so that only the central content changes: 

html.mx body #navBarContainer { view-transition-name: mx-navbar; }

@media screen and (min-width: 769px) {
  html.mx body #leftPaneContainer  { view-transition-name: mx-left; }
  html.mx body #rightPaneContainer { view-transition-name: mx-right; }
}

::view-transition-group(mx-navbar),
::view-transition-group(mx-left),
::view-transition-group(mx-right) { animation: none; }
::view-transition-old(mx-navbar),
::view-transition-old(mx-left),
::view-transition-old(mx-right)   { display: none; }

The side columns are named only on wider screens: on phones they are stacked below the content and have nothing to stay aligned with. Browsers without view transitions simply change page as usual.

Caching

Three things are computed once and kept in the session storage for the rest of the visit:

WhatKeyPost
shared partspartial:v3:<file>shared parts
blog tagsblogTags:v1the blog
search indexsearchIndex:v5site search

All keys include a version number. When the format of what is stored changes, increasing the number makes every browser ignore the old copy, instead of reading data it no longer understands. The session storage is per tab and is cleared when the tab is closed, so a visitor never sees content that is out of date for long.

For the files themselves, GitHub Pages sends caching headers and serves them from a content delivery network close to the visitor; there is nothing to configure.

Images and phones

Images

Photos and screenshots are saved in WebP, which is usually much smaller than JPEG or PNG at the same visual quality. Most image editors can export it, and on the command line: 

cwebp -q 80 photo.jpg -o photo.webp

Images are also resized to the size at which they are displayed: a 4000-pixel photo shown 300 pixels wide wastes bandwidth. Embedded content such as the map on the contacts page fades in once loaded, instead of appearing as an empty box.

Phones

Every page is checked at phone width (375 px): the navigation bar wraps, the CV dates move above the text, buttons take the full width, and no element is wider than the screen. A horizontal scrollbar on a phone almost always comes from a single element that is too wide: a long code line (give pre blocks overflow-x: auto), a table, or an image without max-width: 100%.

Checking before publishing

Before merging into main, the pages are opened in a headless browser (Chrome without a window), which takes screenshots in light and dark mode, at desktop and phone width: 

google-chrome --headless=new --window-size=1280,2000 \
  --screenshot=home.png http://localhost:8000/

google-chrome --headless=new --window-size=375,2000 \
  --screenshot=home-phone.png http://localhost:8000/

Looking at a few screenshots takes a minute and catches most broken layouts, without clicking through every page by hand.
