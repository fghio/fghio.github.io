Introduction

The previous posts covered the main features. This one collects the details that do not add features but make the website feel quicker and more consistent.

Transitions between pages

Recent browsers can animate the change from one page to the next of the same website (view transitions). One line enables them; the shared parts are given a name, so the browser treats them as the same element on both pages and swaps them instantly, while only the central content changes: 

@view-transition { navigation: auto; }

html.mx body #navBarContainer   { view-transition-name: mx-navbar; }
html.mx body #leftPaneContainer { view-transition-name: mx-left; }

::view-transition-group(mx-navbar),
::view-transition-group(mx-left) { animation: none; }

Browsers that do not support view transitions just change page as usual.

Caching

Several things are computed once and kept for the rest of the visit, in the session storage: the shared parts (shared parts), the blog tags (the blog) and the search index (site search). The keys include a version number (partial:v3:, searchIndex:v5): when the format changes, increasing the number makes every browser discard the old copy.

Images

Photos and screenshots are saved in WebP, which is much smaller than JPEG or PNG at the same quality. The map on the contacts page fades in only once it has loaded, instead of appearing as an empty box.

Phones

Every page is checked at phone width (375 px): the navigation bar wraps, the CV dates move above the text, the buttons get the full width, and no element is wider than the screen.

Checking the result

Before publishing, the pages are opened in a headless browser (Chrome without a window) that takes screenshots in light and dark mode, at desktop and phone width. It is a quick way to catch a broken layout without clicking through every page by hand.

The end

This is the end of the series. The overview is a good place to come back to for the overall picture; the source code of the whole website is public on GitHub.
