Introduction

All the pages of this website share the same structure: a navigation bar, three columns and a footer. In this post we build that layout and give it a consistent style. The goal is a stylesheet organised so that changing a colour or a font means editing one line, and so that the dark theme of the next posts comes almost for free.

We use two stylesheets: a base theme that provides the grid and the components, and a small stylesheet of our own, loaded after it, that holds all the visual choices.

The three-column grid

Bulma

The layout uses Bulma, a CSS framework based on flexbox. This website loads it through default.css, a stylesheet adapted from the Icarus theme, which adds components such as cards and the navigation bar. You can use Bulma directly from its CDN if you start from scratch: 

<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/bulma@0.9.4/css/bulma.min.css">

Bulma describes the layout with classes. A columns element contains one column per column, and modifier classes set the width of each column at each screen size, in twelfths of the available width:

ClassMeaning
is-6-widescreen6/12 of the width on screens wider than 1216 px
is-8-desktop8/12 on screens from 1024 px
is-8-tablet8/12 on screens from 769 px
(none)on phones, every column takes the full width and they stack

A complete page

This is the skeleton shared by all the pages, ready to be copied: 

<!DOCTYPE html>
<html lang="en" class="mx">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Jane Doe</title>
  <link rel="stylesheet" href="assets/css/default.css">
  <link rel="stylesheet" href="assets/css/modern.css">
  <link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Inter:wght@400;500;600;700&display=swap">
</head>
<body>
  <nav class="navbar">...</nav>

  <section class="section">
    <div class="container">
      <div class="columns">

        <div class="column column-main order-2 is-8-tablet is-8-desktop is-6-widescreen">
          <div class="card"><div class="card-content">
            <h1 class="title">Welcome</h1>
            <p>The content of the page.</p>
          </div></div>
        </div>

        <div class="column column-left order-1 is-4-tablet is-4-desktop is-3-widescreen">
          <div class="card"><div class="card-content">Profile</div></div>
        </div>

        <div class="column column-right order-3 is-4-tablet is-4-desktop is-3-widescreen">
          <div class="card"><div class="card-content">Links</div></div>
        </div>

      </div>
    </div>
  </section>

  <footer class="footer">...</footer>
</body>
</html>

Notice that the central column comes first in the HTML, although it is displayed in the middle. The content is the most important part of the page: putting it first helps screen readers and search engines, and on a phone (where the columns stack in HTML order) the reader sees the content before the side columns. The order-1, order-2, order-3 classes then place the columns left, centre and right on wider screens.

The right column on medium screens

Between 769 and 1280 px there is not enough room for three columns. A small script, columns.js, moves the content of the right column into a container at the bottom of the left column, and moves it back when the window is enlarged. Nothing is lost on medium screens, and nothing is duplicated in the HTML.

A stylesheet of our own

The base theme gives the structure. All the visual choices (fonts, colours, spacing, borders) are in a second stylesheet, modern.css, loaded after the base one. Keeping them separate has two advantages: the base theme is never edited, so it can be updated or replaced, and the whole restyle can be switched off by removing one line.

Winning over the base theme

When two CSS rules apply to the same element, the more specific one wins. To make sure our rules always win, without writing !important everywhere, every rule of modern.css starts with html.mx, a class set on the <html> element of each page: 

<html lang="en" class="mx">
/* base theme */
.card { box-shadow: 0 4px 10px rgba(0,0,0,.1); }

/* ours: one class and one element more, so it wins */
html.mx body .card { box-shadow: none; border: 1px solid var(--border); }

The extra class has a second benefit: removing class="mx" from a page shows it with the original theme, which is handy to compare before and after.

Colours and fonts as variables

Colours, font, corner radius and shadows are defined once, as CSS custom properties (variables), at the top of the stylesheet. Every other rule uses the variables instead of writing values directly: 

:root {
  --accent: #1a3a6e;          /* PoliMi navy: links, buttons, highlights */
  --accent-hover: #0f2a55;
  --accent-soft: #e7edf7;     /* light background for tags and code */
  --bg: #ffffff;
  --card-bg: #ffffff;
  --text: #1f2633;
  --text-muted: #5b6475;      /* dates, captions */
  --border: #e3e7ee;
  --radius: 6px;
  --radius-sm: 4px;
  --font-body: "Inter", system-ui, -apple-system, "Segoe UI", sans-serif;
  --font-mono: "JetBrains Mono", ui-monospace, monospace;
}

html.mx body          { background: var(--bg); color: var(--text); font-family: var(--font-body); }
html.mx body a        { color: var(--accent); }
html.mx body .card    { background: var(--card-bg); border: 1px solid var(--border);
                        border-radius: var(--radius); box-shadow: none; }
html.mx body .tag     { background: var(--accent-soft); color: var(--accent); }

Changing the accent colour of the whole website is now a one-line change. More importantly, the dark theme becomes a second set of values for the same variables: no rule has to be written twice (see dark mode).

The style

The style is deliberately minimal, in the spirit of academic websites: one sans-serif font (Inter) for everything, one accent colour, thin borders instead of shadows, generous white space and a small, consistent set of font sizes. Cards, CV entries, tags and buttons are all built from the same few variables, which keeps every page consistent with the others.

Choosing a font

Inter is loaded from Google Fonts with the <link> shown in the skeleton above. The font-family lists fallbacks: if Inter is not available yet, the browser uses the system font (system-ui), which avoids invisible text while the font is loading.

Phones

Bulma already stacks the columns on phones. A few more rules adapt the rest, in @media blocks placed next to the rules they modify: 

@media screen and (max-width: 768px) {
  /* the navigation bar wraps onto two lines instead of overflowing */
  html.mx body .navbar-container { flex-wrap: wrap; }

  /* CV entries: the dates go above the text instead of beside it */
  html.mx body .cv-entry { flex-direction: column; }
  html.mx body .cv-entry .left-column { width: auto; }
}

To check the result without a phone, open the browser's developer tools (F12) and switch to the device toolbar: 375 px is a good width to test, as it is one of the narrowest common screens.

Try it yourself

  1. Copy the skeleton into index.html, with Bulma from its CDN.
  2. Create assets/css/modern.css with the variables above and load it after Bulma.
  3. Change --accent and watch links and tags change colour together.
  4. Narrow the window and check the order of the columns on a phone.
