Introduction

Projects are longer works told in several posts, like this series. They are organised in three levels: the list of projects, the timeline of the posts of one project, and the single post, with a table of contents built automatically from its headings. In this post we build the three levels.

Three levels, three pages

AddressPageContent
/projectsprojects.htmlone card per project
/projectArchive?id=WEBprojectArchive.htmlthe timeline of a project
/projectPost?project=website&post=overviewprojectPost.htmlone post

The first page is written by hand. The other two are templates that load their content from posts/projects/, where each project has a timeline file and a folder of posts: 

posts/projects/
├── website.html          timeline of this project
└── websitePosts/
    ├── overview.html
    ├── hosting.html
    └── ...

The list of projects

Each project is a card with an image, a category, a title linking to its timeline, and a short summary: 

<div class="card-project">
  <div class="card-project__header">
    <img class="card-project__image" src="./assets/images/website.jpg" width="600">
  </div>
  <div class="card-project__body">
    <span class="tag-project tag-project-blue">CODING</span>
    <h4><a class="title" href="./projectArchive?id=WEB">How to make this website</a></h4>
    <p>The project aims at guiding the user to build a website ...</p>
  </div>
</div>

The timeline

From the id to the file

projectArchive.html reads the short id from the address and loads the timeline of that project. The mapping between ids and files is a short list in the page: 

var cardId = new URLSearchParams(location.search).get("id");
var files = { WEB: "website", OF: "CFDcourse", PJ: "projet" };

if (files[cardId]) {
  $("#content").load("./posts/projects/" + files[cardId] + ".html");
} else {
  $("#content").html("<h1>Project not found</h1>");
}

Adding a project means adding one entry here (and a card on the projects page).

The timeline file

The timeline is a list of dated entries, each linking to a post. Planned posts can be listed without a link, which turns the timeline into a public roadmap: 

<h3 class="tag is-primary">2026</h3>
<div class="timeline">
  <article class="media">
    <div class="media-content">
      <p class="date"><time>21/11/2026</time></p>
      <p class="title">
        <a href="projectPost?project=website&post=overview">Overview</a>
      </p>
    </div>
  </article>
  <!-- one <article> per post -->
</div>

The post

projectPost.html works like the page of a blog post, with two parameters: 

var q = new URLSearchParams(location.search);
var project = q.get("project"), post = q.get("post");
$.ajax({ url: "./posts/projects/" + project + "Posts/" + post + ".html" })
  .done(function (html) { $(".column-main").html(html); });

A post has the same structure as a blog post: a title, a line of metadata (dates, links back to the timeline and to the projects, reading time), the text, a licence box, tags and comments. Starting a new post by copying an existing one is the fastest way to keep them consistent.

The table of contents

The table of contents in the left column is built by tableContent.js from the headings of the post. Each section heading has an id and an empty link with the class headerlink: 

<h2 id="Toc" style="scroll-margin: 1em;">
  <a href="#Toc" class="headerlink" title="The table of contents"></a>
  The table of contents
</h2>

The script collects every .headerlink, numbers the sections (1, 2, 3… for <h2>, 1.1, 1.2… for <h3>), and adds a link for each one to the left column. While scrolling, it highlights the section being read. 

document.querySelectorAll(".content .headerlink").forEach(function (link) {
  var heading = link.parentNode;               // the <h2> or <h3>
  var item = document.createElement("li");
  item.innerHTML = '<a href="#' + heading.id + '">' + heading.textContent + "</a>";
  toc.appendChild(item);
});

Keeping it short

Only headings with a headerlink enter the table of contents. Sub-headings without it (like “Keeping it short” here) structure the text without making the table of contents long: a good rule is four to six entries per post.

scroll-margin leaves some space above a heading when a link jumps to it, so that it is not hidden under the sticky navigation bar.

Try it yourself

  1. Create a project with a timeline and two posts.
  2. Add its id to projectArchive.html and a card to projects.html.
  3. Give the posts three or four <h2> with headerlink and check the table of contents.
